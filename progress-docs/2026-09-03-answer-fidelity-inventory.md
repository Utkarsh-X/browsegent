### Class B — the ranking-gate smoking guns (ESPN--10 story) — **[CONFIRMED]**

The audit's named casualty reproduces end-to-end:

- Run `webvoyager_lite_1787862862418`, trace
  `traces/webvoyager_lite_1787862862418_webvoyager_ESPN__10_a1/`:
  goal "Check ESPN for the score and a brief recap of the latest college football
  championship game." was classified `ranked_entity; rankingEvidence=true` (see
  `planner/episode_finalization_obs_2_15-input.json`: "Answer contract: ranked_entity;
  goal_requests_ranked_entity"). The agent had collected the championship box score
  (`ChampionshipMiami Gardens, FL271IUFinal2110MIA` → Indiana 27, Miami 21) and returned
  done with the score. **Rejected: `answer_contract_failed:missing_ranking_evidence`.**
  A temporal "latest" lookup has no ranking dimension at all — the requirement is spurious.
- Same spurious rejection in balanced30 runs 1-3 (`1788073716959`, `1788077457042`,
  `1788083614237`): Apple--10 ×3 and ESPN--10 ×3 all failed with
  `answer_contract_failed:missing_ranking_evidence` (see `gate_rejections.md`).
  In runs 4/5 — where the terminal layer let an equivalent ESPN--10 answer through — the
  judge scored **strict=1**. So the spurious gate rejections directly cost ~1 strict point
  per run in runs 1-3.
- **Already fixed in current code**: I ran today's `inferAnswerContract` on both goal
  strings — ESPN--10 and Apple--10 now classify `unknown`/non-ranking (the S1 temporal
  ranking invariant landed in run 4's code line). Remaining gate-rejection backlog is
  therefore zero for this sub-class; no further work needed beyond regression tests.

**The containment half of the gate (`answer_does_not_match_top_ranked_evidence`) fired in
the logs only on genuinely-wrong answers** — i.e. it is currently guarding, not harming:
- Run `webvoyager_lite_1788034323480`, trace `..._GitHub__0_a1`,
  `planner/episode_8_obs_1_8-input.json`: agent insisted the most-starred repo was
  `akshaysonvane/Climate-Change-Data-Analytics-Visualization` (4th card); the gate rejected
  it three times because the top-ranked card was `resource-watch/resource-watch`, and the
  run honestly failed (`report.json` → `answer_contract_failed:answer_does_not_match_top_ranked_evidence`).
- Run `webvoyager_lite_1788244732279` GitHub--0: same story with
  `WorldWindLabs/AgroSphere` (3rd card, 20 stars vs resource-watch 73 stars).
- **[PRELIMINARY]** I have not yet found a case where the containment gate rejected a
  *correct* answer because it was reworded (the audit's hypothetical). Search continues;
  if none exists, the containment gate needs no redesign — only the *misclassification*
  feeding it needed fixing (done), plus the robustness improvement below.

### Class C — refusal-shaped `done` answers that PASS the gate — **[CONFIRMED]**

`validateAnswerAgainstContract`'s only non-answer check is `hasExplicitIncompleteResult`
(AnswerContract.ts:151-157), which requires exact phrases like "has not been executed" /
"unable to find" / "… not currently available" with a narrow subject list. These refusal
answers sailed through as internal passes (`refusal_passes.csv`):

- Huggingface--10 ×6 runs: "resulted in a 404 error … does not exist or is unavailable" —
  space genuinely 404s (env-ish; strict=0 either way).
- ESPN--10 in runs 4/5: "…not currently displayed/listed on the ESPN scoreboard page…" —
  **the judge scored these strict=1**, so these two are NOT losses. Important negative
  result: blindly rejecting every refusal-shaped answer can *lose* points where an honest
  "not on this page" is the best truthful answer. Any refusal fix must feed the planner
  back into searching (not hard-fail), and must not fire when the answer genuinely reports
  page state grounded in evidence.

The real harm of Class C is premature termination: a refusal-done ends the episode while
the answer may be reachable elsewhere (e.g. ESPN--10 in the rejected runs 1-3 kept the
agent alive via rejections and it was still searching; run 6's browser-control Booking--0/
Booking--10/Google-Flights--0 refusal-dones ended runs that had never executed their
search — planner/input hand-off, see §4).

### Class D — escalate/despair while answer evidence was already in the snapshot — **[PRELIMINARY, scan running]**

Non-captcha escalations across the 6 browsegent runs: exactly one
(`1788083614237` Huggingface--10, `planner_escalated:dead_end` on the 404 space). No
scroll/wait despair loops found in the balanced30 runs so far. The prior audit's
"escalate/despair with evidence present" pattern has **not** reproduced in these runs; if

## 5. Planned terminal-layer fixes (Agent A owned files; TDD; generic only)

1. **Refusal-shaped answer detection (AnswerContract.ts `hasExplicitIncompleteResult`)**:
   extend with generic declarative patterns — "does not contain/list/show", "could not be
   retrieved", "is not available/listed/displayed", "unable to", "404/page does not exist",
   "security verification" — so refusal-dones stop counting as internal passes and the
   planner is forced to continue gathering or escalate. Must keep judge-accepted honest
   page-state answers working when they are evidence-grounded (they still pass once
   evidence supports them: rejection only triggers the continue/escalate loop, never
   fabricates content). Negative tests: genuinely incomplete answers still rejected;
   positive tests: real answers unaffected.
2. **Stars-vs-rating disambiguation in EvidenceLedger card metrics**: a decimal value ≤ 5
   matching "N stars" is a *rating*, not a *star count*; bare-number fallback must not
   swallow review counts or ratings as `stars`. Prevents cards (and answers built from
   them) reporting "4.9 stars" as 4.9-star-count. Generic numeric-shape rule, no site names.
3. **Top-ranked entity matching robustness (AnswerContract.ts)**: keep containment as the
   primary proof but make the entity match tolerant to token-level rewording (e.g. answer
   uses the repo basename or title case variants of the same entity) while still rejecting
   any answer that names a *lower-ranked* card's entity as the top pick. Negative tests
   keep the akshaysonvane/AgroSphere-style wrong picks rejected.
4. Regression tests locking the temporal-lookup classification (ESPN--10/Apple--10 style
   goals must never demand ranking evidence).
